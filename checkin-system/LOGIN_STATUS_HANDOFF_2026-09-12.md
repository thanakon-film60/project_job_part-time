# ส่งต่อทีมแอพ: อ่านสถานะยืนยันประจำวันไม่สำเร็จ

วันที่รายงาน: 12 กันยายน 2026 (เวลาไทย)

## ✅ ผลวินิจฉัยและการแก้ไข (12 ก.ย. 2026 — ปิดประเด็นแล้ว)

> ส่วนนี้เพิ่มหลังตรวจจริง ข้อความเดิมทั้งหมดด้านล่างเก็บไว้ตามต้นฉบับ

### สาเหตุที่แท้จริง

**แอปบนมือถือล้ำหน้า backend ที่ deploy อยู่** — ไม่ใช่ปัญหา login, ไม่ใช่เน็ต, ไม่ใช่เซิร์ฟเวอร์ล่ม

| ชั้น | สถานะจริงที่ตรวจพบ |
| --- | --- |
| แอปในมือถือ | `1.6.0+8` (พนักงาน) / `1.3.0+5` (หัวหน้า) — เรียก `/home-verifications/*` |
| backend production | รัน **51 endpoints** และ **ไม่มี `home-verifications` เลยสักเส้น** (ตรวจจาก `/openapi.json`) |
| IIS `web.config` | กฎ `ProxyToBackend` **ไม่มี `home-verifications`** |

หลักฐานชี้ขาด:

```text
GET https://thanakronpart-time.com/home-verifications/me
HTTP 200  content-type: text/html      ← หน้า React ไม่ใช่ API
```

IIS ไม่รู้จักเส้นทางนี้ จึงตกไปเข้ากฎ `StaticFiles` แล้วตอบ `index.html` กลับมาพร้อมรหัส **200**
แอปพยายาม `jsonDecode` HTML → พัง → การ์ดขึ้นว่าอ่านสถานะไม่สำเร็จ

**เป็นบั๊กตัวเดียวกับ `/payroll` ที่บันทึกไว้ใน Work Log วันที่ 12 ก.ย.** — เพิ่ม router ใหม่แล้วลืมเติมชื่อในกฎ proxy

### ตอบข้อสงสัยในรายงานเดิม

| ข้อสงสัยเดิม | ผลตรวจ |
| --- | --- |
| "login ไม่ได้" | ❌ **ไม่จริง** — `POST /auth/login` ตอบ `401 application/json` พร้อมข้อความไทยถูกต้อง auth ทำงานปกติ และภาพหน้าจอก็แสดงว่าล็อกอินอยู่แล้ว |
| `/app/info` = `1.2.0+3` ขณะที่ source = `1.5.0+7` | ✅ จริง แต่**ไม่เกี่ยวกับอาการนี้** — เป็นเพราะยังไม่เคย `publish-apk.ps1` เครื่องผู้ใช้ได้ APK มาทางอื่น (ติดตั้งตรงจากเครื่อง dev) |
| สงสัยเซิร์ฟเวอร์ล่ม / รหัสผ่านผิด / รุ่นแอปไม่ตรง | ❌ ทั้งสามข้อไม่ใช่สาเหตุ |
| ผู้ใช้สลับ Wi-Fi/เน็ตมือถือแล้วไม่หาย | ✅ สมเหตุสมผล เพราะไม่ใช่ปัญหาเครือข่ายตั้งแต่แรก — **ข้อความในแอปทำให้เข้าใจผิดและเสียเวลาไล่แก้ผิดทาง** |

### สิ่งที่แก้ไปแล้ว

1. **`deploy/windows-server/web.config`** — เติม `home-verifications` กลับเข้ากฎ `ProxyToBackend`
   (การแก้รอบก่อนค้างอยู่ใน working tree แล้วหายไป ไม่เคยถูก commit จึงไม่เคยขึ้น production)

2. **แอปทั้ง 2 ตัว — แยกสาเหตุความล้มเหลวให้ตรงจริง** (ตอบข้อ 5 และ 6 ของรายงานเดิม)

   เพิ่ม error code ใหม่ใน `api_service.dart`:

   | สถานการณ์ | code | ข้อความที่ผู้ใช้เห็น |
   | --- | --- | --- |
   | ตอบ HTML แทน JSON, หรือ 404/405 ที่ไม่มี `detail.code` | `endpoint_unavailable` | "ฟีเจอร์นี้ยังไม่พร้อมใช้งาน — เซิร์ฟเวอร์ยังไม่ได้อัปเดต **ไม่ใช่ปัญหาอินเทอร์เน็ตของคุณ**" |
   | 401 | `session_expired` | "เซสชันหมดอายุ กรุณาเข้าสู่ระบบใหม่" (ไม่มีปุ่มลองใหม่ เพราะกดไปก็ไม่ช่วย) |
   | เน็ต/timeout | ไม่มี code | "ยังตรวจสอบผลการยืนยันไม่ได้" + ปุ่มลองอีกครั้ง (พฤติกรรมเดิม) |

   > 404 ของ FastAPI เองแนบ `detail.code` มาเสมอ (เช่น `request_not_found`) จึงใช้แยกออกจาก
   > 404 ที่แปลว่า "ไม่มี router นี้" ได้อย่างแม่นยำ ไม่ต้องเดา

3. **เวอร์ชันใหม่:** พนักงาน `1.6.1+9` · หัวหน้า `1.3.1+6`

### ยังต้องทำเพื่อให้ฟีเจอร์ใช้งานได้จริง

การแก้ข้างบนทำให้**ข้อความตรงความจริง** แต่ฟีเจอร์จะยังใช้ไม่ได้จนกว่าจะ deploy backend

รันบน**เครื่อง production** (เครื่อง dev ทำแทนไม่ได้ — ไม่มี IIS/backend):

```powershell
git pull
cd checkin-system\deploy\windows-server
.\deploy-update.ps1          # build React + copy web.config + restart backend + ตรวจ router ครบทุกเส้น
```

ตรวจว่าสำเร็จ — ต้องได้ **401 JSON** ไม่ใช่ 200 HTML:

```powershell
curl.exe -i https://thanakronpart-time.com/home-verifications/me
```

จากนั้นค่อย publish APK ใหม่:

```powershell
.\publish-apk.ps1 -ApkPath '<employee.apk>' -Version '1.6.1+9' -MinSdk 24
.\publish-apk.ps1 -Boss -ApkPath '<boss.apk>' -Version '1.3.1+6' -MinSdk 24
```

ผู้ใช้แจ้งว่า login ไม่ได้ แต่ภาพแสดงหน้าเช็คอินพร้อมรูปโปรไฟล์ และการ์ดยืนยันว่าอยู่บ้านขึ้นว่าอ่านสถานะไม่สำเร็จ จึงควรเริ่มตรวจการเรียก API สถานะยืนยันประจำวันและการจัดการเซสชัน ยังไม่มีหลักฐานพอจะสรุปว่ารหัสผ่านผิด เซิร์ฟเวอร์ล่ม หรือรุ่นแอพไม่ตรงเป็นสาเหตุแน่นอน

ผู้ใช้ต้องการให้ทีมที่พัฒนาแอพดำเนินการแก้ไขต่อทันที รายงานนี้เป็นผลวินิจฉัยเบื้องต้น ยังไม่ได้แก้โค้ดหรือ deploy

## สิ่งที่ยังไม่ทราบ

- แอพที่ติดตั้งเป็นแอพพนักงานหรือหัวหน้า รวมถึง version/build number และแหล่งติดตั้ง
- source commit/branch และ API base URL ที่ใช้ build แอพในภาพ
- method/path ของ request ที่ทำให้การ์ดนี้ผิดพลาด
- HTTP status, response body ที่ตัดข้อมูลส่วนตัวออกแล้ว และ exception จริง
- token หมดอายุหรือไม่ และ backend มี endpoint/สัญญาข้อมูลที่แอพรุ่นนี้ต้องการหรือไม่
- มีการบันทึกยืนยันสำเร็จก่อนอ่านสถานะล้มเหลวหรือไม่

## งานที่ให้ทีมแอพตรวจและแก้ไข

1. ระบุ APK ที่เกิดปัญหาให้ตรงก่อน: version/build number, บทบาทแอพ, source commit และ API base URL ตรวจเทียบกับ backend ที่ deploy จริง ไม่อาศัย `/app/info` เพียงอย่างเดียว
2. เปิดหน้าตามภาพด้วยบัญชีทดสอบ แล้วจับ request ของการโหลดสถานะยืนยันบ้านและการกด “ลองอีกครั้ง” บันทึก method/path, HTTP status, error code, เวลา และ request ID หากมี ห้ามบันทึก token, รหัสผ่าน, ภาพใบหน้า หรือข้อมูลส่วนตัวลง log
3. ตรวจ backend log ในช่วงเดียวกัน แยกให้ได้ว่าเป็น 401/403, 404/405, 5xx, timeout, TLS หรือ parse response ไม่ผ่าน อย่าสรุปทุกกรณีว่าเป็นอินเทอร์เน็ต
4. แก้ตามหลักฐาน: เซสชันหมดอายุให้เข้าสู่ขั้นตอน login ที่ชัดเจน; endpoint/สัญญาไม่ตรงให้แก้การเชื่อมต่อและ deployment ให้เข้ากัน; response ผิดรูปแบบให้แก้ parser/contract; 5xx ให้แก้ backend ตาม log
5. หาก backend ยังไม่รองรับฟังก์ชัน ให้แสดงว่าฟังก์ชันยังไม่พร้อมใช้งาน ไม่ให้ผู้ใช้ติดอยู่กับการลองใหม่โดยไม่มีคำอธิบาย และห้ามข้ามการยืนยันใบหน้าเพื่อแสดงว่าสำเร็จ
6. แยกข้อความ “อ่านผลไม่ได้” ออกจาก “ยังไม่ได้ยืนยัน” และ “เซสชันหมดอายุ” ให้ตรงกับเหตุจริง การโหลดสถานะล้มเหลวต้องไม่ถูกแสดงเป็นการยืนยันล้มเหลวแน่นอน
7. หากคำขอบันทึกอาจสำเร็จแล้วแต่การตอบกลับหาย ให้ตรวจผลคำขอเดิมก่อนสร้างรายการใหม่ ป้องกันการบันทึกซ้ำตามสัญญา request ID ของระบบ
8. ตรวจและปรับ metadata ดาวน์โหลดให้ตรงกับ APK ที่เผยแพร่จริงหลังยืนยัน artifact แล้ว

ก่อนแก้ source ให้ปฏิบัติตาม `project_job_part-time/AGENTS.md` ซึ่งกำหนดให้ทำ impact analysis ก่อนแก้ฟังก์ชัน และตรวจ graph changes ก่อน commit

## เกณฑ์ตรวจรับหลังแก้

- บัญชีที่ token ใช้ได้เปิดหน้านี้และโหลดสถานะจริงได้ ทั้ง Wi-Fi และเน็ตมือถือ
- token หมดอายุแสดงเหตุผลและไป login ได้ ไม่ค้างอยู่ที่ข้อผิดพลาดเครือข่ายทั่วไป
- กรณีไม่มีรายการวันนี้แสดงว่ายังไม่ได้ยืนยันเฉพาะเมื่อ API ยืนยันว่าไม่มีรายการ
- กรณียืนยันแล้วแสดงผลจาก server ถูกต้อง กด retry หรือเปิดแอพซ้ำไม่เพิ่มรายการ
- จำลอง timeout, 404 และ 5xx แล้วข้อความ/แนวทางแก้แยกสาเหตุได้
- บ้านไม่ถูกนับเป็นเวลาเข้างาน/ออกงานหรือชั่วโมงทำงาน
- ทดสอบกับ APK ที่จะส่งจริง และบันทึก version/build, commit, environment, ผลทดสอบ และข้อจำกัดที่ยังเหลือ
