วันที่รายงาน: 12 กันยายน 2026 (เวลาไทย)

## อัปเดตหลังแก้ server — 12 กันยายน 2026 เวลา 14:27 น.

ยืนยันสาเหตุแล้ว: backend ยังไม่มี home-verification router และ IIS ส่งเส้นทางนี้ไปหน้า React (`200 text/html`) แทน API นำโค้ด server จาก `origin/Film_dev_Part-Time` (`bd5989c`) มาใช้ พร้อมเติมค่า Settings 3 ตัวที่ขาด จากนั้น deploy backend/IIS สำเร็จ

ตรวจโดเมนจริงแล้ว: ไม่ส่ง token ได้ `401 application/json`; มี token พนักงานและหัวหน้าอ่าน `/home-verifications/me` ได้ `200` พร้อม JSON สถานะรายวันและ `no-store`; OpenAPI มี 56 paths รวม home verification 5 paths; ตาราง PostgreSQL ใหม่ครบ 2 ตาราง ชุดทดสอบฐานข้อมูลแยกผ่าน 108 กรณี

ยังไม่ได้ publish APK ใหม่เพราะไม่มี artifact รุ่นที่ทีมแอพระบุในเครื่องนี้ และยังไม่ได้ทดสอบสแกน/GPS บนมือถือจริง ดูรายละเอียดและงานที่เหลือใน [SERVER_DEPLOY_HOME_VERIFICATION_2026-09-12.md](SERVER_DEPLOY_HOME_VERIFICATION_2026-09-12.md)

## สรุปเพื่อเริ่มงาน

ผู้ใช้แจ้งว่า login ไม่ได้ แต่ภาพแสดงหน้าเช็คอินพร้อมรูปโปรไฟล์ และการ์ดยืนยันว่าอยู่บ้านขึ้นว่าอ่านสถานะไม่สำเร็จ จึงควรเริ่มตรวจการเรียก API สถานะยืนยันประจำวันและการจัดการเซสชัน ยังไม่มีหลักฐานพอจะสรุปว่ารหัสผ่านผิด เซิร์ฟเวอร์ล่ม หรือรุ่นแอพไม่ตรงเป็นสาเหตุแน่นอน

ผู้ใช้ต้องการให้ทีมที่พัฒนาแอพดำเนินการแก้ไขต่อทันที รายงานนี้เป็นผลวินิจฉัยเบื้องต้น ยังไม่ได้แก้โค้ดหรือ deploy

## ผลตรวจที่ยืนยันแล้ว

### เซิร์ฟเวอร์สาธารณะ

ตรวจจากเครื่องพัฒนาผ่านเครือข่ายที่อนุญาต:

```text
GET https://thanakronpart-time.com/health
HTTP 200
{"status":"ok"}
```

ผลนี้ยืนยันเฉพาะ health endpoint ณ เวลาตรวจ ไม่ได้ยืนยันว่า API ที่ต้องใช้ token, ฐานข้อมูล หรือ API ยืนยันบ้านทำงานครบ

```text
GET https://thanakronpart-time.com/app/info
{
  "available": true,
  "filename": "thanakon-checkin.apk",
  "download_url": "/app/download",
  "size_bytes": 78240434,
  "built_at": "2026-08-25T12:26:50Z",
  "version": "1.2.0+3",
  "min_android": "7.0 (API 24)"
}
```

หมายเหตุ: การตรวจครั้งแรกภายใน sandbox เชื่อมต่อไม่ได้ แต่เมื่อตรวจผ่านเครือข่ายที่อนุญาตแล้ว health ตอบ 200 จึงไม่นับความล้มเหลวครั้งแรกเป็นหลักฐานว่าเซิร์ฟเวอร์ล่ม

## สิ่งที่ยังไม่ทราบ

- แอพที่ติดตั้งเป็นแอพพนักงานหรือหัวหน้า รวมถึง version/build number และแหล่งติดตั้ง
- source commit/branch และ API base URL ที่ใช้ build แอพในภาพ
- method/path ของ request ที่ทำให้การ์ดนี้ผิดพลาด
- HTTP status, response body ที่ตัดข้อมูลส่วนตัวออกแล้ว และ exception จริง
- token หมดอายุหรือไม่ และ backend มี endpoint/สัญญาข้อมูลที่แอพรุ่นนี้ต้องการหรือไม่
- มีการบันทึกยืนยันสำเร็จก่อนอ่านสถานะล้มเหลวหรือไม่

## งานที่ให้ทีมแอพตรวจและแก้ไข

1. ระบุ APK ที่เกิดปัญหาให้ตรงก่อน: version/build number, บทบาทแอพ, source commit และ API base URL ตรวจเทียบกับ backend ที่ deploy จริง ไม่อาศัย `/app/info` เพียงอย่างเดียว
2. เปิดหน้าตามภาพด้วยบัญชีทดสอบ แล้วจับ request ของการโหลดสถานะยืนยันบ้านและการกด “ลองอีกครั้ง” บันทึก method/path, HTTP status, error code, เวลา และ request ID หากมี ห้ามบันทึก token, รหัสผ่าน, ภาพใบหน้า หรือข้อมูลส่วนตัวลง log
3. ตรวจ backend log ในช่วงเดียวกัน แยกให้ได้ว่าเป็น 401/403, 404/405, 5xx, timeout, TLS หรือ parse response ไม่ผ่าน อย่าสรุปทุกกรณีว่าเป็นอินเทอร์เน็ต
4. แก้ตามหลักฐาน: เซสชันหมดอายุให้เข้าสู่ขั้นตอน login ที่ชัดเจน; endpoint/สัญญาไม่ตรงให้แก้การเชื่อมต่อและ deployment ให้เข้ากัน; response ผิดรูปแบบให้แก้ parser/contract; 5xx ให้แก้ backend ตาม log
5. หาก backend ยังไม่รองรับฟังก์ชัน ให้แสดงว่าฟังก์ชันยังไม่พร้อมใช้งาน ไม่ให้ผู้ใช้ติดอยู่กับการลองใหม่โดยไม่มีคำอธิบาย และห้ามข้ามการยืนยันใบหน้าเพื่อแสดงว่าสำเร็จ
6. แยกข้อความ “อ่านผลไม่ได้” ออกจาก “ยังไม่ได้ยืนยัน” และ “เซสชันหมดอายุ” ให้ตรงกับเหตุจริง การโหลดสถานะล้มเหลวต้องไม่ถูกแสดงเป็นการยืนยันล้มเหลวแน่นอน
7. หากคำขอบันทึกอาจสำเร็จแล้วแต่การตอบกลับหาย ให้ตรวจผลคำขอเดิมก่อนสร้างรายการใหม่ ป้องกันการบันทึกซ้ำตามสัญญา request ID ของระบบ
8. ตรวจและปรับ metadata ดาวน์โหลดให้ตรงกับ APK ที่เผยแพร่จริงหลังยืนยัน artifact แล้ว

ก่อนแก้ source ให้ปฏิบัติตาม `project_job_part-time/AGENTS.md` ซึ่งกำหนดให้ทำ impact analysis ก่อนแก้ฟังก์ชัน และตรวจ graph changes ก่อน commit

## เกณฑ์ตรวจรับหลังแก้

- บัญชีที่ token ใช้ได้เปิดหน้านี้และโหลดสถานะจริงได้ ทั้ง Wi-Fi และเน็ตมือถือ
- token หมดอายุแสดงเหตุผลและไป login ได้ ไม่ค้างอยู่ที่ข้อผิดพลาดเครือข่ายทั่วไป
- กรณีไม่มีรายการวันนี้แสดงว่ายังไม่ได้ยืนยันเฉพาะเมื่อ API ยืนยันว่าไม่มีรายการ
- กรณียืนยันแล้วแสดงผลจาก server ถูกต้อง กด retry หรือเปิดแอพซ้ำไม่เพิ่มรายการ
- จำลอง timeout, 404 และ 5xx แล้วข้อความ/แนวทางแก้แยกสาเหตุได้
- บ้านไม่ถูกนับเป็นเวลาเข้างาน/ออกงานหรือชั่วโมงทำงาน
- ทดสอบกับ APK ที่จะส่งจริง และบันทึก version/build, commit, environment, ผลทดสอบ และข้อจำกัดที่ยังเหลือ
