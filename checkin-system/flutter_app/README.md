# แอปเช็คอิน THANAKON-ROOM (Flutter)

แอป Android สำหรับพนักงาน — เช็คอินด้วย GPS + สแกนใบหน้า
คุยกับ backend ตัวเดียวกับเว็บ (ตั้ง URL ที่ `lib/config.dart`)

## build เป็นไฟล์ APK ให้พนักงานโหลดจากเว็บ

รันบนเครื่องที่มี Flutter SDK + Android SDK (เครื่อง production ไม่ต้องมี — ดูหัวข้อถัดไป):

```powershell
.\deploy\windows-server\build-flutter-apk.ps1
```

สคริปต์จะทำให้ทั้งหมดนี้เอง:

1. `flutter create --platforms=android .` ถ้ายังไม่มีโฟลเดอร์ `android/`
   (โฟลเดอร์นี้ไม่ได้ commit ลง git เพราะสร้างใหม่ได้)
2. เติมสิทธิ์กล้อง/ตำแหน่ง/แจ้งเตือน และตั้งชื่อแอปลง `AndroidManifest.xml`
   ตาม [PLATFORM_SETUP.md](PLATFORM_SETUP.md)
3. ตั้ง `minSdk = 23` (ML Kit + background service ต้องการ)
4. สร้างไอคอนแอปจาก **โลโก้ตัวเดียวกับเว็บ** (ดูหัวข้อถัดไป)
5. `flutter build apk --release`
6. copy ไฟล์ไปที่ `backend/storage/app/thanakon-checkin.apk`
   → พนักงานเห็นปุ่มดาวน์โหลดที่หน้าแรกของเว็บทันที ไม่ต้อง deploy เว็บใหม่

หรือสั่งพร้อม deploy เว็บในทีเดียว: `.\BUILD_DEPLOY.ps1 -BuildApk`

## ส่ง APK ขึ้นเครื่อง production

เครื่อง production ไม่มี Flutter SDK และ APK ก็ไม่ได้ commit ลง git (ไฟล์ 70+ MB)
จึงต้อง copy ไฟล์ `.apk` ไปเอง แล้วสั่งบนเซิร์ฟเวอร์:

```powershell
.\deploy\windows-server\publish-apk.ps1 -ApkPath D:\thanakon-checkin.apk
```

สคริปต์จะตรวจว่าไฟล์เป็น APK จริง วางลง `backend/storage/app/` แล้วเขียนเวอร์ชัน/วันที่ build
ลง `release.json` ให้หน้าเว็บ — ไม่ต้อง restart backend และไม่ต้อง deploy เว็บใหม่
เช็กผลที่ `https://thanakronpart-time.com/app/info` (ต้องได้ `"available": true`)

## โครงหน้าจอ: Sidebar + แท็บ

หลังล็อกอินทุกอย่างอยู่ใน `AppShell` ([lib/screens/app_shell.dart](lib/screens/app_shell.dart))
เมนูด้านข้างเป็น **Drawer** บนมือถือ และ **ตรึงไว้ข้างจอ** อัตโนมัติเมื่อจอกว้าง ≥ 900 dp
(แท็บเล็ต/แนวนอน) — ใช้เนื้อหาเมนูชุดเดียวกันทั้งสองแบบ

| แท็บ | ไฟล์ | เนื้อหา |
| --- | --- | --- |
| เช็คอินเข้างาน | `screens/tabs/checkin_tab.dart` | ตำแหน่งปัจจุบัน · สถานะการติดตาม · ลงเวลาวันนี้ · ปุ่มเข้า/ออกงาน |
| ประวัติการลงเวลา | `screens/tabs/history_tab.dart` | ย้อนหลัง 30 วัน กดกางดูรายการของแต่ละวัน |
| สถานที่ & สถานะระบบ | `screens/tabs/places_tab.dart` | รัศมีที่เช็คอินได้ + ระยะห่างตอนนี้ · เหลือเวลาใช้งานอีกเท่าไร |

### เพิ่มแท็บใหม่

1. สร้างไฟล์หน้าจอใน `lib/screens/tabs/` (คืน widget ธรรมดา ไม่ต้องมี `Scaffold`/`AppBar` — shell จัดให้)
2. เพิ่ม `AppTab` หนึ่งตัวใน [lib/navigation/app_tabs.dart](lib/navigation/app_tabs.dart)

```dart
AppTab(
  id: 'leave',
  label: 'ขอลา',
  subtitle: 'ยื่นใบลา / ดูสถานะ',
  icon: Icons.event_busy,
  builder: (_) => const LeaveTab(),
),
```

เท่านี้เมนูขึ้นเอง ทั้งบน Drawer และ sidebar แบบตรึง ไม่ต้องแก้ `AppShell` เลย
ลำดับในลิสต์ = ลำดับบนเมนู

> แท็บถูกเก็บไว้ใน `IndexedStack` — สลับไปมาแล้วสถานะเดิม (ตำแหน่งที่เลื่อน, ข้อมูลที่โหลดไว้)
> ยังอยู่ครบ ไม่ต้องโหลดใหม่ทุกครั้งที่เปลี่ยนแท็บ

### ของที่ต้องเดินตลอด ไม่ผูกกับแท็บ

`AppShell` ถือไว้เองทั้งหมด แท็บจึงเหลือแค่หน้าที่แสดงผล:

- **การติดตามตำแหน่ง** — `TrackingController` ([lib/services/tracking_controller.dart](lib/services/tracking_controller.dart))
  เป็น `ChangeNotifier` ตัวเดียวของทั้งแอป แท็บไหนอยากรู้สถานะก็ `addListener` เอา
- **การทวงสิทธิ์ "อนุญาตตลอดเวลา"** ทุก 10 นาที
- **การเด้งออกจากระบบตอน 4 ทุ่ม**

## รายการลงเวลาของวันนี้ (หน้าแรก)

หลังล็อกอิน หน้าแรกไม่ได้บอกแค่พิกัดกับระยะห่างแล้ว แต่มีการ์ด **"การลงเวลาวันนี้"**
ที่ดึงจาก `GET /checkins/me?days=1` มาแสดงเป็นรายการ (List) ของวันนี้ตามเวลาไทย

| ส่วนที่แสดง | รายละเอียด |
| --- | --- |
| สรุปด้านบน | เข้างานครั้งแรกกี่โมง · ออกงานล่าสุดกี่โมง · รวมเวลาทำงาน (เดินสดทุก 30 วินาที) |
| รายการแต่ละแถว | เข้างาน/ออกงาน · เวลา · ชื่อสถานที่ · ระยะห่าง · ป้าย "นอกเขต" ถ้าอยู่นอกรัศมี |
| สถานะ | "กำลังทำงานอยู่" เมื่อกดเข้างานแล้วยังไม่ได้กดออกงาน |

การจับคู่เข้า-ออกอยู่ใน `lib/services/attendance_service.dart` (มี unit test ครอบใน `test/widget_test.dart`)
เผื่อเคสที่เกิดจริง: กดเข้างานซ้ำ (ยึดครั้งแรก), มีออกงานลอยๆ ไม่มีเข้างานคู่กัน (โชว์ในรายการ แต่ไม่นับเวลา)

รีเฟรชอัตโนมัติทุก 2 นาที + ทุกครั้งที่กลับเข้าแอป + ทันทีหลังลงเวลาสำเร็จ (ดึงหน้าจอลงก็รีเฟรชได้)

> `days` / `limit` เป็นพารามิเตอร์ใหม่ของ backend ถ้าเซิร์ฟเวอร์ยังไม่อัปเดต
> จะคืนประวัติทั้งหมดมาตามเดิม — แอปกรองเฉพาะวันนี้ให้อยู่แล้ว จึงยังทำงานได้ปกติ

## อยู่บ้าน = ไม่ได้ไปทำงาน (ไม่มีออกงาน)

สถานที่ที่ถูกจัดเป็น "บ้าน" (`category: "home"` ใน OFFICES หรือชื่อมีคำว่า บ้าน/home/house)
ไม่ถือเป็นการมาทำงาน กติกาทั้งระบบจึงเป็นแบบนี้:

| สถานการณ์ | ผลลัพธ์ |
| --- | --- |
| อยู่ในเขตบ้าน | หน้าแรกขึ้น "อยู่บ้าน — ไม่ได้ไปทำงาน" ไม่มีปุ่มเข้างาน/ออกงาน |
| กดปุ่มเดียวที่มี | "บันทึกว่าอยู่บ้าน" — ไว้ให้หัวหน้ารู้ว่าวันนี้อยู่บ้าน **ไม่ต้องกดออกงานตามมา** |
| บันทึกว่าอยู่บ้านแล้ววันนี้ | ปุ่มเปลี่ยนเป็น "บันทึกว่าอยู่บ้านแล้วเมื่อ HH:mm น." กดซ้ำไม่ได้ |
| วันที่มีแต่รายการที่บ้าน | สรุปวันนั้นขึ้น "อยู่บ้าน — ไม่ได้ไปทำงาน" รวมเวลาทำงาน `-` และไม่เตือนว่าลืมกดออกงาน |
| เข้างานที่ที่ทำงานไว้ แล้วกลับบ้านโดยไม่ได้กดออก | หน้าแรกเตือนว่ายังค้างการเข้างานอยู่ ต้องไปกดออกงานที่ที่ทำงาน (กดที่บ้านไม่ได้) |

ตรรกะการจับคู่เวลาทำงานอยู่ที่ `DayAttendance._pair` — **กรองรายการที่บ้านออกก่อนเสมอ**
รายการที่บ้านยังโชว์ในลิสต์ว่า "อยู่บ้านแล้ว" (ไอคอนบ้าน สีม่วง) แต่ไม่เปิดช่วงเวลาทำงาน จึงไม่มีวัน
กลายเป็น "ยังไม่ได้กดออกงาน" และไม่ถูกนับเป็นชั่วโมงทำงาน

> ก่อนหน้านี้การกด "ถึงบ้านแล้ว" ถูกนับเป็นเข้างาน ทำให้เวลาทำงานเดินทั้งวันและ
> ขึ้นเตือนว่าลืมกดออกงานทุกวัน — เงื่อนไขนี้แก้ตรงนั้น

> พนักงานยัง **ต้องเข้าสู่ระบบทุกวัน** ถึงจะรู้ว่าใครอยู่ที่ไหน — การอยู่บ้าน
> ไม่ได้แปลว่าไม่ต้องเปิดแอป

ฝั่ง backend และเว็บยึดกติกาเดียวกัน: `/checkins` ปฏิเสธการออกงานที่บ้านอยู่แล้ว
(`work_only` ตัดสถานที่หมวด home ทิ้ง), แจ้ง LINE ว่า "อยู่บ้านแล้ว" แทน "เข้างาน",
สรุปประจำวันแยกคนที่อยู่บ้านออกจากคนที่มาทำงาน, ปฏิทิน (`/reports/calendar`,
`/reports/team-calendar`) ไม่เอาการลงเวลาที่บ้านมาเป็นเวลาเข้า/ออกงาน และส่งฟิลด์
`home_only` ให้เว็บขึ้นป้าย "อยู่บ้าน — ไม่ได้ไปทำงาน" 

## ติดตามตำแหน่งตั้งแต่ล็อกอิน จนกว่าจะออกจากระบบ

การส่งพิกัดเริ่มทันทีที่เข้าหน้าแรก **ไม่ต้องรอกดเข้างาน และไม่สนใจว่าอยู่ในเขตหรือไม่** —
อยู่บ้านแต่ล็อกอินค้างไว้ก็ยังส่งพิกัดทุก 60 วินาที (`Config.pingIntervalSeconds`)
หยุดเมื่อ **ออกจากระบบ** หรือ **ถึง 4 ทุ่ม** เท่านั้น

| เงื่อนไข | พฤติกรรม |
| --- | --- |
| ยังไม่ได้สิทธิ์ "อนุญาตตลอดเวลา" | หน้าแรกขึ้นแถบสีส้มค้างไว้ + ทวงซ้ำทุก 10 นาที (`locationPermissionNagInterval`) จนกว่าจะได้หรือออกจากระบบ |
| Android 11+ | เลือก "อนุญาตตลอดเวลา" จากป๊อปอัปไม่ได้ ระบบบังคับให้ไปกดในหน้าตั้งค่า — ปุ่ม "เปิดหน้าตั้งค่า" พาไปให้ |
| ปิด GPS ทั้งเครื่อง | แถบเปลี่ยนเป็นสีแดง พร้อมปุ่มเปิดหน้าตั้งค่าตำแหน่ง |
| ไม่ได้สิทธิ์แจ้งเตือน | ยังติดตามต่อ เพียงแต่ไม่เห็นแถบ "กำลังติดตามตำแหน่ง" (ของเดิมยกเลิกการติดตามทั้งหมด) |
| ปิดแอป/สลับไปแอปอื่น | foreground service (ชนิด `location`) ยังส่งต่อ และอัปเดตเวลาส่งล่าสุดบนแถบแจ้งเตือน |
| เปิดเครื่องใหม่ | `autoStartOnBoot` เริ่ม service ให้เอง ถ้ายังล็อกอินอยู่ ถ้าไม่ใช่ก็หยุดตัวเองในรอบแรก |
| ระบบประหยัดแบตของเครื่อง | ขอยกเว้น (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) หนึ่งครั้งตอนเริ่มติดตาม ไม่ให้ก็ยังทำงาน แต่พิกัดอาจขาดช่วง |

isolate เบื้องหลังอ่าน token ใหม่ทุกรอบ (`ApiService.loadToken`) จึงรู้ทันทีเมื่อมีการล็อกอินใหม่
หรือถูกเด้งออก แล้ว `stopSelf()` ตัวเองเมื่อไม่มี session เหลือ

## หมดเวลาใช้งานประจำวัน (4 ทุ่ม)

ทุกเครื่องจะถูกเด้งออกจากระบบตอน **22:00 น. เวลาไทย** แล้วต้องล็อกอินใหม่ในวันถัดไป
กันเคสลืมออกจากระบบแล้วเครื่องส่งพิกัด GPS ต่อทั้งคืน และกัน token ค้างในเครื่องที่ทำหาย

| ตอนนั้นแอปอยู่สถานะไหน | เกิดอะไรขึ้น |
| --- | --- |
| เปิดหน้าจอค้างไว้ | Timer ครบเวลา → หยุด background service → กลับไปหน้าล็อกอินพร้อมข้อความบอกเหตุผล |
| ถูกพักไว้เบื้องหลัง / เพิ่งเปิดขึ้นมาใหม่ | เช็กเวลาซ้ำตอน resume และตอนเปิดแอป (`ApiService.loadToken`) |
| ส่งพิกัดอยู่ใน background isolate | `sendPing` เรียก `ensureSession()` ก่อนทุกครั้ง เลยเวลาแล้วจะหยุดส่งเอง |

ตั้งค่าเวลาได้ที่ `lib/config.dart` → `sessionEndHour` / `sessionEndMinute`
(ยึดเวลาไทยด้วย `thaiUtcOffset` ไม่ใช่ timezone ของเครื่อง — มือถือที่ตั้งเวลาผิดจะได้หมดพร้อมกัน)

> เวอร์ชันแรกที่มีเงื่อนไขนี้คือ 1.1.0 — เครื่องที่อัปเดตจากตัวเก่าจะโดนให้ล็อกอินใหม่หนึ่งครั้ง
> เพราะ token เดิมไม่มีเวลาหมดอายุติดมาด้วย

> ฝั่ง backend ยังออก JWT อายุ 12 ชม. ตามเดิม (`access_token_expire_minutes`)
> เงื่อนไข 4 ทุ่มนี้บังคับที่ตัวแอป ถ้าต้องการให้ตัว token หมดอายุจริงตาม ต้องแก้ที่ backend ด้วย
