# ช่วยเหลือระยะไกล (Remote IT support) — วิดีโอคอล + วาดชี้จุดบนภาพ

ผู้ช่วยที่ล็อกอินแล้วเปิด "ห้อง" ส่งลิงก์ให้ผู้ใช้ที่มีปัญหา
ผู้ใช้แค่กดลิงก์แล้วกด **อนุญาตกล้อง** ก็เห็นหน้ากัน คุยกัน และผู้ช่วยวาดวงกลม/ลูกศร
ลงบนภาพจากกล้องของผู้ใช้เพื่อชี้ว่า "ต้องกดตรงนี้" ได้เลย

ผู้ใช้ **ไม่ต้องมีบัญชี ไม่ต้องติดตั้งแอป** — ใช้ได้ทั้งมือถือและคอม

---

## ใช้ยังไง

### ฝั่งผู้ช่วย (ต้องล็อกอิน)

1. เมนูซ้าย → **ช่วยเหลือระยะไกล**
2. กรอกเรื่องที่ต้องแก้ + ชื่อผู้ใช้ → กด **สร้างห้องและคัดลอกลิงก์** (ลิงก์ถูกคัดลอกให้อัตโนมัติ)
3. ส่งลิงก์ให้ผู้ใช้ทาง LINE / แชทในระบบ / อีเมล
   (ถ้าผู้ใช้นั่งอยู่หน้าคอมแต่ต้องใช้มือถือส่องของ ให้กดปุ่ม **QR** แล้วให้เขาสแกน)
4. รอจนป้ายสถานะเปลี่ยนเป็น **เชื่อมต่อแล้ว** แล้วใช้แถบเครื่องมือด้านล่างจอ

| ปุ่ม | ทำอะไร |
|---|---|
| ✏️ ดินสอ / ⭕ วงกลม / ↗️ ลูกศร / ▭ กรอบ | วาดชี้จุดบนภาพของผู้ใช้ — เขาเห็นทันที |
| จุดสี 5 สี + ความหนา 3 ระดับ | เลือกสีที่ตัดกับพื้นหลังของจริง |
| ↩️ ย้อน / 🧽 ลบทั้งหมด | ลบเส้นออกทั้งสองฝั่งพร้อมกัน |
| ❄️ **หยุดภาพ** | ตรึงเฟรมปัจจุบันแล้วส่งภาพนิ่งใบเดียวกันให้ผู้ใช้ดู |
| 🎤 / 📹 | ปิด-เปิดไมค์และกล้องของตัวเอง |
| 📵 | วางสายและปิดห้อง (ลิงก์เดิมใช้ไม่ได้อีก) |

> **❄️ หยุดภาพคือปุ่มที่ใช้บ่อยที่สุด** — เวลาผู้ใช้ถือมือถือส่องของ พอเราวงกลมเสร็จ
> มือเขาขยับไปแล้ว วงกลมเลยไปคร่อมที่ว่าง การตรึงเฟรมเดียวกันทั้งสองฝั่งทำให้ชี้จุดตรงจริง

### ฝั่งผู้ใช้ (ไม่ต้องล็อกอิน)

เปิดลิงก์ → เห็นชื่อผู้ช่วยที่ขอ + สิ่งที่จะเกิดขึ้น → กด **อนุญาตกล้องและไมโครโฟน**
จากนั้นกล้องหลังจะเปิดขึ้นมา (ไว้ส่องอุปกรณ์ที่มีปัญหา) พร้อมปุ่ม:
สลับกล้องหน้า/หลัง · ปิดไมค์ · ปิดกล้อง · **แชร์หน้าจอ** · วางสาย

## ไลบรารีที่ใช้ และทำไมถึงเลือกแบบนี้

| ส่วน | ใช้อะไร | หมายเหตุ |
|---|---|---|
| ภาพ/เสียง | **WebRTC** ในเบราว์เซอร์ | ต่อตรงระหว่างสองเครื่อง ไม่ผ่านเซิร์ฟเวอร์ |
| สัญญาณนัดพบ (SDP/ICE) + เส้นที่วาด | **WebSocket ของ FastAPI (Starlette)** | มีอยู่แล้วใน `uvicorn[standard]` |
| QR ลิงก์เชิญ | **`qrcode`** | ออกเป็น SVG จึงไม่ต้องพึ่ง Pillow |
| หาเส้นทางต่อตรง | **STUN** ของ Google (ฟรี) | ตั้ง TURN เพิ่มได้ถ้าเน็ตบางที่ต่อไม่ติด |

**ลงไลบรารี Python เพิ่มแค่ตัวเดียวคือ `qrcode`** — นอกนั้นใช้ของที่โปรเจ็กต์มีอยู่แล้ว

ที่ **ไม่** เลือกใช้ และเหตุผล:

- **`aiortc`** (WebRTC ฝั่ง Python) — จะทำให้ภาพวิ่งผ่านเซิร์ฟเวอร์โดยไม่ได้อะไรเพิ่ม
  เปลือง CPU/bandwidth และกลายเป็นจุดที่วิดีโอของพนักงานผ่านตาเซิร์ฟเวอร์โดยไม่จำเป็น
  ถ้าวันหนึ่งอยาก **อัดวิดีโอเก็บไว้** ค่อยเพิ่ม `aiortc` เป็น peer อีกตัวได้ โดยไม่ต้องแก้ฝั่งหน้าเว็บเลย
- **บริการสำเร็จรูป (Twilio / Agora / Daily)** — คิดเงินตามนาที และต้องส่งวิดีโอออกนอกบริษัท
- **`python-socketio`** — WebSocket ของ Starlette พอแล้วสำหรับห้องละ 2 คน ไม่ต้องเพิ่ม dependency

## ติดตั้ง

```bash
cd backend
pip install -r requirements.txt     # ได้ qrcode มาด้วย
```

บน production (Windows Server + IIS) ต้องทำเพิ่ม **2 อย่าง**:

```powershell
# 1) เปิด WebSocket ของ IIS — ไม่เปิด หน้าเว็บจะค้างที่ "กำลังเชื่อมต่อ..." โดยไม่มี error
Install-WindowsFeature Web-WebSockets

# 2) copy web.config ตัวใหม่ (มี support ในกฎ ProxyToBackend แล้ว)
copy deploy\windows-server\web.config C:\inetpub\<site>\web.config
```

แล้ว restart backend — ตาราง `support_sessions` ถูกสร้างอัตโนมัติตอนสตาร์ต

## ค่าใน `.env`

| ค่า | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `SUPPORT_SESSION_TTL_MINUTES` | `120` | ลิงก์เชิญอายุกี่นาที |
| `SUPPORT_MAX_OPEN_SESSIONS` | `5` | เปิดห้องค้างพร้อมกันได้กี่ห้องต่อคน |
| `SUPPORT_PUBLIC_BASE_URL` | ว่าง | โดเมนสำหรับประกอบลิงก์ (เว้นว่าง = ใช้โดเมนที่เปิดหน้าเว็บอยู่) |
| `STUN_SERVERS` | STUN ของ Google | คั่นด้วยจุลภาค |
| `TURN_URL` / `TURN_USERNAME` / `TURN_PASSWORD` | ว่าง | ใช้เมื่อ STUN อย่างเดียวต่อไม่ติด |

## API

| Method | Path | ใครเรียกได้ |
|---|---|---|
| POST | `/support/sessions` | ผู้ช่วยที่ล็อกอิน — เปิดห้องใหม่ |
| GET | `/support/sessions` | ผู้ช่วย — ห้องของตัวเอง 20 ห้องล่าสุด |
| GET | `/support/sessions/{code}` | เจ้าของห้องเท่านั้น |
| POST | `/support/sessions/{code}/end` | เจ้าของห้อง — ปิดห้อง + ไล่ทั้งสองฝั่งออกทันที |
| GET | `/support/sessions/{code}/qr.svg` | เจ้าของห้อง — QR ของลิงก์เชิญ |
| GET | `/support/guest/{code}` | **ไม่ต้องล็อกอิน** — ชื่อผู้ช่วย + เข้าได้ไหม |
| GET | `/support/ice-servers` | **ไม่ต้องล็อกอิน** — ค่า STUN/TURN |
| WS | `/support/ws/{code}?role=host&token=…` / `?role=guest` | ส่งต่อข้อความระหว่างสองฝั่ง |

## ความปลอดภัย

- **ลิงก์คือกุญแจ** — โทเค็นสุ่ม 32 ตัวอักษร (`secrets.token_urlsafe`) เดาไม่ได้ในทางปฏิบัติ
  แต่ใครถือลิงก์ก็เข้าได้ จึงมี **วันหมดอายุเสมอ** และควรส่งผ่านช่องทางที่เชื่อถือได้
- **ผู้ใช้เห็นชื่อคนขอก่อนกดอนุญาต** — ตั้งใจใส่ไว้ เพราะการเปิดกล้องให้คนแปลกหน้าคือความเสี่ยง
  หน้าจอมีข้อความเตือนด้วยว่า "ถ้าไม่รู้จักชื่อด้านบน อย่ากดอนุญาต"
- **เซิร์ฟเวอร์ไม่เห็นวิดีโอ** และไม่มีการบันทึกภาพหรือเสียงลงดิสก์เลย
- **ส่งต่อเฉพาะข้อความที่อยู่ในรายการอนุญาต** (`RELAYABLE` ใน `app/routers/support.py`)
  ห้องนี้จึงกลายเป็นช่องส่งข้อมูลอะไรก็ได้ระหว่างคนนอกสองคนไม่ได้
- **โทเค็นของผู้ช่วยส่งทาง query string** เพราะ WebSocket ในเบราว์เซอร์ตั้ง header `Authorization` ไม่ได้
  โทเค็นจึงอาจติดไปกับ log ของ proxy — ถ้ากังวลให้ลด `ACCESS_TOKEN_EXPIRE_MINUTES` ลง
- **ต้องเป็น https** — WebRTC และ `getUserMedia` ใช้ไม่ได้บน http ธรรมดา (ยกเว้น `localhost`)

## แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| ค้างที่ "กำลังเชื่อมต่อ..." ไม่ขยับ | IIS ยังไม่ได้เปิด `Web-WebSockets` หรือ `web.config` ยังไม่มี `support` ในกฎ proxy |
| ผู้ใช้กดปุ่มอนุญาตแล้วไม่มีอะไรเกิดขึ้น | เปิดลิงก์ผ่าน http — ต้องเป็น https |
| ขึ้น "ต่อสายไม่สำเร็จ" ทั้งที่สองฝั่งออนไลน์ | เน็ตฝั่งใดฝั่งหนึ่งบล็อก UDP (เจอบ่อยกับ Wi-Fi บริษัท) → ต้องตั้ง TURN |
| เสียงสะท้อน/หอน | ทั้งสองฝั่งอยู่ห้องเดียวกันจริง ๆ ให้ฝั่งหนึ่งปิดไมค์ |
| ปุ่ม QR กดแล้วขึ้น error | ยังไม่ได้ `pip install -r requirements.txt` ตัวใหม่ (ขาด `qrcode`) — ส่งลิงก์แทนได้ |
| วงกลมที่วาดไปอยู่คนละที่ | ผู้ใช้ขยับมือถือระหว่างวาด → กด ❄️ หยุดภาพก่อนวาด |
