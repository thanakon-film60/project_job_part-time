### ทำไมถึงด่วน

APK ที่หัวหน้าใช้อยู่ตอนนี้ **เก่ากว่าโค้ด 3 วัน**

| อย่าง | เวลา |

แปลว่าทุกอย่างที่แก้ไปในรอบนี้ — ปุ่มฟังเสียงที่โผล่เองเมื่อกลับเข้าแท็บ,
ปุ่ม "ลองเช็คใหม่" — **ยังไม่มีในเครื่องหัวหน้าเลย** ต่อให้เซิร์ฟเวอร์พร้อม 100%
หัวหน้าก็ยังเจอข้อความ "เซิร์ฟเวอร์นี้ยังส่งเสียงจากกล้องไม่ได้" ค้างเหมือนเดิม

### ⚠️ แอปหัวหน้าไม่มีระบบเตือนอัปเดต

ต่างจากแอปพนักงาน — แอปหัวหน้า **ไม่เช็คเวอร์ชันใหม่ให้เอง** โดยตั้งใจ
([`profile_tab.dart:241-243`](lib/screens/tabs/profile_tab.dart#L241-L243) อธิบายไว้ว่า
ถ้าไปเทียบกับ `/app/info` หัวหน้าจะกดโหลดได้ APK ของ *แอปพนักงาน* มาทับ)

**ผลคือไม่มีใครรู้ว่าต้องอัปเดต จนกว่าจะมีคนเดินไปบอก** — ต้องส่งไฟล์ให้หัวหน้าเอง
พร้อมบอกให้ถอนตัวเก่าออกก่อนติดตั้ง (คนละ signing key อาจติดตั้งทับไม่ได้)


`https://thanakronpart-time.com` อยู่แล้ว จะชี้ production ให้เองถ้าไม่ส่ง `--dart-define`

ไฟล์ที่ได้:



แล้วแก้ `storage\boss-app\release.json` ให้ตรงกับเวอร์ชันใหม่:

## งานที่ 2: ขยับเลขเวอร์ชันก่อน build

ตอนนี้เลขซ้ำกันหมด **แยกไม่ออกว่าเครื่องไหนมีของใหม่แล้ว**

| ที่ | ค่าปัจจุบัน |
|---|---|
| `pubspec.yaml` บรรทัด 4 | `1.0.0+1` |
| [`lib/config.dart` บรรทัด 10](lib/config.dart#L10) | `"1.0.0"` |
| `storage/boss-app/release.json` (ตัวที่เผยแพร่) | `1.0.0+1` |

ถ้า build ทับโดยไม่ขยับเลข หัวหน้าเปิดหน้า "เวอร์ชันแอป" ก็ยังเห็น `1.0.0`
เหมือนเดิมทั้งเครื่องเก่าเครื่องใหม่ เวลามีปัญหาจะไล่ไม่ถูกว่าใครอัปแล้วบ้าง

**ต้องแก้ 2 ที่ให้ตรงกัน** (คอมเมนต์ใน `config.dart` เตือนไว้แล้วว่าต้องแก้คู่กัน
เพราะแอปอ่านจาก `pubspec` ตอนรันไม่ได้):

```yaml
# pubspec.yaml
version: 1.1.0+2
```

```dart
// lib/config.dart
static const String appVersion = "1.1.0";
```

## ของที่ทำไปแล้ว (อย่าทำซ้ำ)

ทีมแอปแก้ครบตามที่เคยขอไปแล้ว ตรวจในโค้ดปัจจุบันยืนยันแล้วทั้งหมด:

| สิ่งที่เคยขอ | สถานะ | อยู่ที่ |
|---|---|---|
| โหลดสถานะใหม่เมื่อกลับเข้าแท็บ | ✅ แล้ว | `didChangeDependencies` → `_refreshStatusIfStale()` |
| โหลดสถานะใหม่เมื่อแอปกลับมา foreground | ✅ แล้ว | `didChangeAppLifecycleState` → `_refreshStatusIfStale()` |
| กันยิงถี่เกินไป | ✅ แล้ว | `_statusFresh` + `_statusFreshTimer` |
| ปุ่ม "ลองเช็คใหม่" ข้างข้อความ | ✅ แล้ว | `_buildUnavailableNote(showRetry: true)` |

ฝั่ง backend ก็แก้ครบแล้วเช่นกัน (ฆ่า ffmpeg ทั้ง process tree, ใช้สตรีมร่วมกันทุกคน,
ตั้งเพดานอายุสตรีม, ถามกล้องเรื่อง talkback เองแทนที่จะเขียนตายตัว)

## งานที่ 5: (ไม่ด่วน) just_audio ค้างสาย 77 วินาที

ตอนผู้ใช้กดหยุดฟัง ตัวเล่นเสียงบน Android **ไม่ยอมปิดการเชื่อมต่อ** วัดได้ว่า
สายยังค้างอยู่อีก **77 วินาที** สาเหตุคือ `just_audio` ตั้งพร็อกซีในเครื่อง
เพื่อแนบ header ให้ ExoPlayer สั่งหยุดแล้วพร็อกซีตัวนั้นยังคาสายไว้
เซิร์ฟเวอร์จึงไม่มีทางรู้ว่าเลิกฟังแล้ว และต้องเลี้ยง ffmpeg ค้างไว้เปล่า ๆ

**ตอนนี้ฝั่งเซิร์ฟเวอร์แก้ด้วยทางอ้อมไปแล้ว** — ตั้งเพดานอายุสตรีม
`CAMERA_AUDIO_MAX_SECONDS=600` ครบเวลาแล้วตัดเอง ไม่ถึงขั้นพัง

ฝากทีมแอปพิจารณาว่าปิดสายให้ขาดจริงตอนกดหยุดได้ไหม (เช่นเปลี่ยนวิธีแนบ header
หรือ dispose player แทนการ pause) ถ้าทำได้จะดีกว่าเพราะ:

- ทรัพยากรถูกคืนทันทีที่กดหยุด ไม่ต้องรอ 10 นาที
- โควตาการเชื่อมต่อของกล้องมีจำกัด ยิ่งคืนเร็วยิ่งดี

> ระวัง: `just_audio` กับ `audio_session` ถูกตรึงเวอร์ชันไว้ใน `pubspec.yaml`
> **อย่าอัปเกรดจนกว่าจะขยับ AGP เป็น 9** (มีคอมเมนต์อธิบายไว้ในไฟล์)

ติดตั้ง APK ใหม่แล้วเปิดแท็บ "กล้องวงจรปิด" ต้องได้ครบ:

- [ ] เห็นภาพสด มีป้าย **LIVE** สีแดง (ไม่ใช่ "ภาพค้าง" สีส้ม)
- [ ] ปุ่มทิศทางกดแล้วกล้องหมุนจริง
- [ ] เห็นปุ่ม **"ฟังเสียงจากกล้อง"** (ไม่ใช่ข้อความสีจาง)
- [ ] กดแล้วได้ยินเสียงภายในราว 10 วินาที
- [ ] สลับไปแท็บอื่นแล้วกลับมา — สถานะยังถูกต้อง ไม่ค้างค่าเก่า
