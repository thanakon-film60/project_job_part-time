# แจ้งเตือนรอบเงินเดือนเข้า LINE

สรุปรายได้เข้า LINE อัตโนมัติ 3 จังหวะต่อรอบ โดยคำนวณจากการลงเวลาจริงในระบบ

| วันที่ | ส่งอะไร | ส่งเวลา |
|---|---|---|
| **26** | 🧾 **ตัดรอบแล้ว** — รอบนี้มีโอกาสได้เงินเท่าไร | 18:00 (รอให้ลงเวลาออกงานครบก่อน) |
| **27** | 🚀 **เริ่มรอบใหม่** — ต้องมากี่วัน มาครบแล้วได้เท่าไร | 09:00 |
| **28** | 💰 **เงินเดือนออก** — สรุปยอดที่เข้าบัญชีวันนี้ | 09:00 |

---

## รอบเงินเดือนทำงานยังไง

```
   27 ส.ค. ─────────── รอบหนึ่งรอบ ─────────── 26 ก.ย.    28 ก.ย.
      │                                            │          │
   เริ่มนับ                                     ตัดรอบ      จ่ายเงิน
```

**จุดที่คนอ่านโค้ดพลาดบ่อยที่สุด:** วันที่ 28 **ไม่ได้อยู่ในรอบที่กำลังจ่าย**
วันที่ 28 อยู่ในรอบใหม่ (ที่เริ่มไปแล้วเมื่อวันที่ 27) แต่เงินที่จ่ายเป็นของรอบเก่า
โค้ดจึงแยกเป็นสองฟังก์ชันที่ห้ามใช้สลับกัน:

| ฟังก์ชัน | ตอบคำถาม |
|---|---|
| `period_containing(day)` | วันนี้อยู่รอบไหน |
| `period_paid_on(day)` | เงินที่จ่ายวันนี้เป็นของรอบไหน |

## วิธีคิดเงิน

```
รายได้ก่อนหัก (gross)
  − หักขาดงาน       = ค่าแรงต่อวัน × วันทำงานที่ไม่มีการลงเวลา
  − หักมาสาย        = ปิดไว้เป็นค่าเริ่มต้น (เปิดที่ PAYROLL_LATE_DEDUCTION_PER_DAY)
  − ประกันสังคม     = 5% ของยอดที่จ่าย ฐาน 1,650–15,000 บาท (สูงสุด 750)
  ─────────────────
  = ยอดสุทธิที่แจ้งใน LINE
```

### รายได้ก่อนหักคิดยังไงเมื่อเริ่มงานกลางรอบ

เลือกได้ 2 แบบที่ `PAYROLL_PRORATE_BASIS` — **แก้ 1 บรรทัดใน `.env` ไม่ต้องแก้โค้ด**

| ค่า | สูตร | ตัวอย่าง: เงินเดือน 18,000 เริ่มงาน 14 ก.ย. รอบ 27 ส.ค.–26 ก.ย. |
|---|---|---|
| `calendar_30` (ค่าเริ่มต้น) | เงินเดือน ÷ 30 × วันตามปฏิทินที่อยู่ในรอบ | 14–26 ก.ย. = 13 วัน → 18,000÷30×13 = **฿7,800** |
| `work_days` | เงินเดือน ÷ วันทำงานทั้งรอบ × วันทำงานที่มีสิทธิ์ | วันทำงาน 10 จาก 22 วัน → 18,000÷22×10 = **฿8,182** |

> `calendar_30` เป็นค่าเริ่มต้นเพราะเป็นวิธีที่ HR ไทยใช้บ่อยที่สุดกับพนักงานเข้าใหม่
> **ยืนยันกับ HR ในวันเริ่มงานแล้วค่อยเปลี่ยนถ้าไม่ตรง**

ทำงานเต็มรอบ (เริ่มงานก่อนวันที่ 27 ของเดือนก่อน) ได้เงินเดือนเต็มเสมอทั้งสองแบบ

### วันไหนนับว่า "มาทำงาน"

ใช้เกณฑ์เดียวกับปฏิทินบนเว็บและข้อความแจ้งเข้างาน เพื่อไม่ให้ตัวเลขขัดกันเอง:

- เป็นการลงเวลา `in` · อยู่ในเขต (`within_geofence`) · จุดที่ลงไม่ใช่ประเภท `home`
- **วันหนึ่งนับครั้งเดียว** แม้กดหลายรอบ
- **"สาย" ยึดการกดครั้งแรกของวัน** — กดซ้ำตอนบ่ายไม่ทำให้กลายเป็นสาย

### วันหยุดไม่ใช่วันขาดงาน

เสาร์–อาทิตย์และวันที่อยู่ใน `PAYROLL_HOLIDAYS` ถูกตัดออกจาก "วันที่ต้องมาทำงาน"
ไม่ได้ถูกนับเป็นขาดงาน

> ⚠️ **ไม่ใส่วันหยุดนักขัตฤกษ์ = โดนหักเงิน** ระบบไม่รู้จักวันหยุดราชการเอง
> ต้องกรอกใน `PAYROLL_HOLIDAYS` เอง

## ติดตั้ง

### 1. ตั้งค่าใน `backend/.env`

```env
PAYROLL_ENABLED=true
PAYROLL_CUTOFF_DAY=26
PAYROLL_PAYDAY=28
PAYROLL_PRORATE_BASIS=calendar_30

# ⚠️ เงินเดือนเป็นข้อมูลส่วนตัว — ตั้งเป็นแชทส่วนตัว อย่าปล่อยให้เข้ากลุ่มทีม
PAYROLL_LINE_TARGET_ID=Uxxxxxxxxxxxxxxxx

# วันหยุดนักขัตฤกษ์ของรอบถัดๆ ไป
PAYROLL_HOLIDAYS=2026-10-13,2026-10-23
```

ค่าที่เหลือดูทั้งหมดใน `backend/.env.example`

> **`PAYROLL_LINE_TARGET_ID` สำคัญกว่าที่คิด** — ถ้าเว้นว่าง ข้อความเงินเดือนจะไป
> เข้าห้องเดียวกับแจ้งเตือนเข้างาน ซึ่งเป็น**กลุ่มที่มีหัวหน้าและเพื่อนร่วมงานอยู่**
> หา userId ของตัวเองได้โดยทักบอทในแชทส่วนตัวแล้วพิมพ์ `id`

### 2. ตั้งเงินเดือนของพนักงาน

เลือกทางใดทางหนึ่ง:

```powershell
# ทาง A — ตั้งรายคนผ่าน API (หัวหน้าเท่านั้น) แนะนำเมื่อมีหลายคน
curl -X PUT https://thanakronpart-time.com/payroll/employees/1/salary `
     -H "Authorization: Bearer <token ของหัวหน้า>" `
     -H "Content-Type: application/json" `
     -d '{"base_salary": 18000, "start_date": "2026-09-14"}'
```

```env
# ทาง B — ตั้งใน .env ให้มีผลกับทุกคนที่ยังไม่ได้ตั้งรายคน
PAYROLL_DEFAULT_SALARY=18000
```

> คนที่ไม่มีเงินเดือนตั้งไว้จะ **ไม่เข้าระบบเงินเดือนและไม่ถูกแจ้งเตือน** —
> ตั้งใจให้ค่าเริ่มต้นปลอดภัย ไม่มีใครถูกส่งตัวเลขเงินเดือนโดยไม่ได้ตั้งใจ

**อย่าลืม `start_date`** — เป็นตัวที่ทำให้รอบแรกคิดเงินไม่เต็มเดือน
ไม่ตั้งไว้ ระบบจะถือว่าทำงานมาตั้งแต่ต้นรอบและคิดเต็มเดือนให้

### 3. restart backend หนึ่งครั้ง

ตาราง `payroll_notices` และคอลัมน์ `employees.base_salary` ถูกสร้างให้อัตโนมัติ
ตอนสตาร์ต (`Base.metadata.create_all` + `apply_pending_migrations`)

```powershell

```


### API

| Method | Path | สิทธิ์ | ใช้ทำอะไร |
|---|---|---|---|
| `GET` | `/payroll/summary` | ล็อกอิน | ยอดสะสมของรอบปัจจุบัน — เปิดดูได้ตลอด ไม่ต้องรอวันตัดรอบ |
| `GET` | `/payroll/summary?which=previous` | ล็อกอิน | รอบก่อนหน้า (`current` / `previous` / `next` / `paid_today`) |
| `GET` | `/payroll/summary?employee_id=2` | หัวหน้า | ยอดของพนักงานคนอื่น |
| `GET` | `/payroll/status` | หัวหน้า | สถานะระบบ + รอบปัจจุบัน + ใครอยู่ในระบบเงินเดือน |
| `PUT` | `/payroll/employees/{id}/salary` | หัวหน้า | ตั้งเงินเดือน + วันเริ่มงาน |
| `POST` | `/payroll/notify?kind=cutoff&dry_run=true` | หัวหน้า | สั่งส่ง/ดูข้อความทันที |
| `POST` | `/payroll/run-due` | หัวหน้า | ส่งทุกใบที่ถึงกำหนดแล้ว |

> พนักงานทั่วไปดูได้เฉพาะยอดของตัวเอง — `/payroll/status` มีเงินเดือนของทุกคนอยู่
> จึงเป็นของหัวหน้าเท่านั้น

## ทำไมข้อความถึงสวย — ใช้อะไร

ใช้ **LINE Flex Message** ซึ่งเป็นของที่ Messaging API มีให้อยู่แล้ว
**ไม่ได้ลงไลบรารีเพิ่มแม้แต่ตัวเดียว**

การลง `line-bot-sdk` จะลาก `aiohttp`/`requests` เข้ามาโดยไม่ได้อะไรเพิ่ม เพราะ
`notify_line.py` ยิง HTTP ด้วย `urllib` จาก stdlib อยู่แล้ว — Flex ต่างจากข้อความ
ธรรมดาแค่ส่ง JSON คนละรูปแบบเท่านั้น (`app/line_flex.py` เป็นตัวประกอบ JSON นั้น)

ข้อจำกัดของ Flex ที่โค้ดกันไว้แล้ว:
- `altText` ยาวได้ 400 ตัวอักษร (เกินแล้ว LINE ตีกลับทั้งข้อความ) — ตัดที่ 390
- สีต้องเป็น `#RRGGBB` เท่านั้น ชื่อสีอย่าง `red` ใช้ไม่ได้ (มีเทสต์คุม)
- `altText` ต้องอ่านรู้เรื่องด้วยตัวเอง เพราะคือสิ่งที่โผล่ในรายการแชทและบนนาฬิกา

## กันส่งซ้ำ

ทุกใบที่ส่งสำเร็จถูกบันทึกใน `payroll_notices` — Scheduled Task ยิงวันละ 2 รอบ
และกดสั่งเองได้อีก แต่จะได้ข้อความเดิมครั้งเดียวต่อรอบ

- ส่งไม่สำเร็จ (`ok=False`) → รอบถัดไปลองใหม่ให้เอง
- อยากส่งซ้ำจริงๆ → `--force` หรือ `?force=true`
- `--dry-run` ไม่บันทึก จึงไม่ทำให้ของจริงถูกข้าม

**ตกรอบเพราะเครื่องดับ:** สคริปต์มองย้อนหลังได้ตาม `PAYROLL_NOTICE_CATCHUP_HOURS`
(ค่าเริ่มต้น 36 ชม.) เครื่องดับคืนวันที่ 26 กลับมาเช้าวันที่ 27 ก็ยังได้ข้อความตัดรอบ
เกินจากนั้นถือว่าตกรอบ ไม่ส่ง — กันสแปมย้อนหลังหลายรอบรวดเดียว

## ข้อจำกัดที่รู้อยู่

| ข้อจำกัด | ผลที่ตามมา |
|---|---|
| **ไม่รู้จักวันลา** | ลาป่วย/ลากิจถูกนับเป็นขาดงานและโดนหักเงิน — ใส่เป็นวันหยุดใน `PAYROLL_HOLIDAYS` ไปก่อน |
| **ไม่คิดภาษีหัก ณ ที่จ่าย** | ยอดสุทธิยังไม่หักภาษี (เงินเดือน 18,000 ปกติภาษีเป็นศูนย์อยู่แล้วหลังหักลดหย่อน) |
| **ไม่คิด OT / เบี้ยขยัน / ค่าคอม** | มีแค่เงินเดือนฐาน ขาดงาน และประกันสังคม |
| **เวลาทำงานเป็นค่าเดียวทั้งระบบ** | รองรับหลายกะไม่ได้ (ข้อจำกัดเดิมของ `work_schedule.py`) |
| **คำนวณสดทุกครั้ง ไม่ล็อกสถานะ** | แก้เกณฑ์ย้อนหลังแล้วตัวเลขรอบเก่าเปลี่ยนตาม — `payroll_notices.amount` เก็บยอดที่เคยแจ้งไว้ให้ตรวจย้อนหลังได้ |
| **ตัวเลขเป็นการประมาณ** | ยอดจริงยึดตามสลิปเงินเดือนจากฝ่ายบุคคลเสมอ (เขียนไว้ท้ายการ์ดทุกใบ) |
