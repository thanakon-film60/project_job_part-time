# แชทบนเว็บไซต์ — 10 กันยายน 2026

## วิธีใช้งาน

หลังเข้าสู่ระบบ กด **แชท** ที่มุมขวาล่างของทุกหน้าเพื่อเปิด/ยุบกล่องสนทนา
หัวหน้าเลือกพนักงานได้ และพนักงานเลือกหัวหน้าได้ เป็นบทสนทนาส่วนตัวระหว่างสองคน
ค้นหาจากชื่อ/รหัสพนักงาน แล้วพิมพ์ข้อความและกดปุ่มส่ง หรือ Enter (Shift+Enter ขึ้นบรรทัดใหม่)

- ข้อความยาวได้ 2,000 ตัวอักษร แสดงเวลาไทยและสถานะส่งแล้ว/อ่านแล้ว
- แสดงจำนวนข้อความที่ยังไม่อ่านข้างปุ่มแชทและรายชื่อ
- ยุบแชทหรือเปลี่ยนหน้าภายในเว็บได้โดยข้อความที่กำลังพิมพ์ยังอยู่; รีเฟรช/ออกจากระบบจะล้างร่าง
- ประวัติข้อความที่ส่งสำเร็จเก็บในฐานข้อมูล อ่านย้อนหลังได้ด้วยปุ่ม “ข้อความก่อนหน้า”
- ถ้าส่งไม่สำเร็จ ข้อความยังอยู่ให้กดส่งใหม่ โดยใช้รหัสเดิมป้องกันการบันทึกซ้ำเมื่อคำตอบจากเซิร์ฟเวอร์หาย
- อัปเดตข้อความทุกประมาณ 3 วินาทีเมื่อเปิดบทสนทนา; รายชื่อทุก 5 วินาทีเมื่อเปิด และ 10 วินาทีเมื่อยุบ พักเมื่อแท็บถูกซ่อน

## โครงสร้าง

`backend/app/chat_models.py`: ตารางใหม่ `chat_messages` พร้อม index คู่สนทนา/ข้อความยังไม่อ่าน และ unique `(sender_id, client_id)`

`backend/app/routers/chat.py`: ทุก endpoint ใช้บัญชีจาก JWT ฝั่ง backend ไม่เชื่อ sender_id ที่ client ส่ง

| Endpoint | หน้าที่ |
| --- | --- |
| GET `/chat/contacts` | เฉพาะรายชื่อฝั่งตรงข้าม พร้อมข้อความล่าสุดของคู่สนทนาตนและจำนวนยังไม่อ่าน |
| GET `/chat/messages/{peer_id}` | ประวัติส่วนตัว พร้อม `before_id` หรือ `after_id`, จำกัด 100 รายการต่อคำขอ |
| POST `/chat/messages/{peer_id}` | ส่งข้อความด้วย `body` และ UUID `client_id`; retry รหัสเดิมคืนข้อความเดิม |
| POST `/chat/read/{peer_id}` | อ่านข้อความจากคู่สนทนาถึง `through_id` ที่อยู่ในบทสนทนานั้นเท่านั้น |

`frontend/src/components/ChatWidget.jsx`: กล่องยุบ–ขยายที่ติดตั้งใน `App.jsx` จึงรักษาร่างเมื่อเปลี่ยนหน้า
API client เพิ่มใน `frontend/src/api.js`; ป้องกัน cache ด้วย `no-store` และเพิ่ม `/chat` ใน PWA denylist
เพิ่ม `chat` ในกฎ IIS `deploy/windows-server/web.config` เพื่อส่ง API ไป backend

เมื่อ restart backend, การ import router ลงทะเบียน model ก่อน `Base.metadata.create_all()` จะสร้างตารางใหม่โดยไม่แก้ตารางประวัติลงเวลาเดิม

## การทดสอบ

รันจาก `checkin-system`:

```powershell
Push-Location backend
.\venv\Scripts\python.exe -m unittest test_chat -v
Pop-Location
npm --prefix frontend run build
```

9 tests ผ่าน: authentication, สิทธิ์คู่สนทนา, การป้องกันอ่านบทสนทนาคนอื่น, unread/read boundary, idempotency, validation/ปลอมผู้ส่ง, pagination และ no-store

ทดสอบเบราว์เซอร์ด้วย API จริงและ SQLite ชั่วคราว (ไม่ใช้ฐานข้อมูลหรือบัญชี production):

```powershell
# dependency สำหรับทดสอบเท่านั้น; เครื่องต้องมี Microsoft Edge
npm --prefix frontend install --no-save --package-lock=false playwright
Push-Location backend
.\venv\Scripts\python.exe test_chat_browser.py
Pop-Location
```

ผ่านสองหน้าต่างหัวหน้า–พนักงาน, หน้าจอมือถือ 390px/เดสก์ท็อป 1440px, ส่งกลับข้อความไทย, unread/อ่านแล้ว, ยุบและร่าง, เปลี่ยนหน้า, โหลดประวัติหลัง refresh, เน็ตหลุดหลัง server รับข้อความแล้วไม่เกิดรายการซ้ำ, HTML แสดงเป็นข้อความ และปุ่ม Escape

GitNexus impact ก่อนแก้ `App` และ backend `app/main.py`: LOW; จุดเชื่อมตรงคือ frontend `main.jsx` และ backend `tests_e2e.py` ตามลำดับ ไม่ได้ commit ในรอบนี้
